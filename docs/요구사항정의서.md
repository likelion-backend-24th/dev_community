# 요구사항 정의서

## 0. 프로젝트 개요

MVP1 - 개발자를 대상으로 한 질문/답변, 정보나눔 등의 기능과. 유료 구독 서비스를 갖춘 게시판을 개발하기에 앞서, 기초적이고 다른 프로젝트에도 통용될 수 있는 게시판 구조를 만드는 것을 목표로 한다.

## MVP2 - 결제/구독(Mock PG, 프리미엄 게시판)으로 수익화 구조를 만들고, GitHub/Google 로그인으로 가입 진입장벽을 낮추며, 평판 시스템·파일 첨부·마크다운 지원으로 커뮤니티 참여와 콘텐츠 품질을 강화하는 확장 단계

## MVP1

## 1. 기능

#### \* 사용자 유형

| 역할             | 설명                                                           |
| ---------------- | -------------------------------------------------------------- |
| 비로그인         | 질문/답변 목록·상세·검색 조회만 가능                           |
| USER (일반 회원) | 조회 + 질문/답변 작성·수정·삭제(본인 글에 한함) + 추천/채택 등 |
| ADMIN (관리자)   | USER 권한 + 타 사용자 게시물 관리, 신고 처리, 통계 조회 등     |

#### \* 권한 원칙

- 모든 쓰기 작업(질문/답변 작성, 수정, 삭제, 추천 등)은 로그인한 사용자만 수행 가능
- 본인이 작성한 게시물/답변만 수정·삭제 가능 (ADMIN은 예외적으로 전체 관리 가능)
- 관리자 전용 기능(신고 처리, 통계 대시보드 등)은 ADMIN 역할만 접근 가능

## 4. 비기능 요구사항

- API 응답: JSON 통일 형식(성공/에러 공통 포맷)
- 목록 조회 기본 `page size`: 10
- 비밀번호: BCrypt 암호화 저장
- 토큰: Access Token 단기 만료 + Refresh Token 재발급 구조 (Refresh Token은 Redis 등에 저장해 서버 측 무효화 가능하도록 함)
- 소프트 삭제 대상: 회원, 질문, 답변 (물리 삭제 없음)
- **API 문서화**: Swagger/OpenAPI로 API 스펙 공유
- **로깅**: 요청/에러 로그 최소 기록 (운영 중 장애 추적용)
- **환경 분리**: local/dev/prod 프로파일 분리 (`application.yml`)
- **DB 스키마 관리**: 개발 초기엔 `ddl-auto`로 진행하되, 배포 전 Flyway 등 마이그레이션 도구 도입 검토
- **초기 데이터**: 관리자 계정 및 기본 태그는 `CommandLineRunner` 또는 시드 스크립트로 생성
- **조회 성능**: 질문 목록 조회 시 답변 수·태그 등 연관 데이터 조회로 인한 N+1 문제 방지 (fetch join 또는 별도 집계 쿼리)
