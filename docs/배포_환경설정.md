# 배포 및 환경설정

dev_com 서비스의 실행 환경(profile), 환경변수, 로컬 개발 세팅, CI/CD 파이프라인, 프로덕션 인프라 구성을 정리한 문서.

> **2026-08-27 인프라 분리 이전**: AWS 프리티어 크레딧 소진에 대응해 단일 EC2 인스턴스가 담당하던 DB·백엔드·프론트를 역할별 영구 무료 플랜으로 분리 (DB → Aiven, 프론트 → Vercel, 백엔드 → GCP e2-micro). **이 문서는 그 이후 기준으로 갱신**
> 배경/문제 해결 과정은 README `## 배포` 섹션의 `EC2 종료와 배포 구조 이전` 참고.

- **프론트 (Live)**: https://dev-community-neon.vercel.app (Vercel, GitHub 연동 자동 배포)
- **백엔드 API**: https://dev-com.duckdns.org (GCP Compute Engine e2-micro · DuckDNS · Let's Encrypt)
- **DB**: Aiven 관리형 MySQL (Free tier, 북미 리전)
- **저장소**: https://github.com/likelion-backend-24th/dev_community

## 2. 실행 환경(Spring Profile)

`application.yml`의 공통 설정 + profile별 override 파일 구조

| Profile | 파일                    | 사용처                | DB / Redis                                  | 특징                                                                                                                                                |
| ------- | ----------------------- | --------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `local` | `application-local.yml` | 개발자 로컬           | `localhost:3306` / `localhost:6379`         | `show-sql: true`, `cookie.secure=false`, frontend-url `http://localhost:5173`, Swagger 활성                                                         |
| `ci`    | `application-ci.yml`    | GitHub Actions 테스트 | 서비스 컨테이너 (더미 계정)                 | JWT/PortOne 시크릿이 커밋된 더미값. `local`이 `.gitignore` 대상이라 CI에서 이 파일로 대체                                                           |
| `prod`  | `application-prod.yml`  | GCP e2-micro 배포     | `${DB_HOST}`(Aiven 외부 호스트) / `redis`(컨테이너명, compose에 고정값) | `show-sql: false`, `cookie.secure=true`, `server.forward-headers-strategy: framework`, **Swagger/OpenAPI 비활성**, GitHub scope에 `user:email` 포함 |

- 기본 활성 profile은 `local` (`application.yml`의 `spring.profiles.active`).
- 배포 시 `docker-compose.prod.yml`의 `SPRING_PROFILES_ACTIVE: prod`로 지정.
- CI 실행 시 `.github/workflows/ci.yml`에서 `SPRING_PROFILES_ACTIVE: ci`.

### 공통 고정 설정 (`application.yml`)

| 항목             | 값                                                 |
| ---------------- | -------------------------------------------------- |
| JPA `ddl-auto`   | `update` (local/prod 모두)                         |
| 파일 업로드      | 파일당 2MB, 요청당 10MB                            |
| JWT Access 만료  | 900,000ms (15분)                                   |
| JWT Refresh 만료 | 1,209,600,000ms (14일)                             |
| 메일             | `smtp.gmail.com:587`, STARTTLS                     |
| Gemini 모델      | `gemini-flash-lite-latest`                         |
| 업로드 경로      | local `uploads`, prod `/app/uploads` (볼륨 마운트) |

## 3. 환경변수

### 3.1 백엔드 (`backend/.env` - `.env.example` 복사 후 작성)

로컬에서는 `backend/.env`를 `backend/docker-compose.yml`(MySQL/Redis)과 `./gradlew bootRun`이 읽고, 프로덕션에서는 GCP 서버의 프로젝트 루트 `.env`를 `docker-compose.prod.yml`이 읽음.

| 변수                                                   | 필수 | 설명                                                                      |
| ------------------------------------------------------ | ---- | ------------------------------------------------------------------------- |
| `DB_HOST`                                              | ✅   | prod는 Aiven 호스트(예: `xxx.aivencloud.com`), local은 `localhost`        |
| `DB_PORT`                                              | ✅ (prod) | prod는 Aiven이 발급한 포트(예: `13697`, 3306 아님). local 기본 `3306` |
| `DB_NAME`                                              | ✅ (prod) | prod는 Aiven 기본 DB명(예: `defaultdb`)                              |
| `DB_SSL_MODE`                                          | ✅ (prod) | Aiven 연결 시 `REQUIRED`. local은 비워둠                              |
| `DB_ROOT_PASSWORD`                                     | (local만) | MySQL root 비밀번호 (로컬 `backend/docker-compose.yml` 컨테이너 초기화용, prod는 미사용) |
| `DB_USER`                                              | ✅   | 앱이 사용하는 DB 계정                                                     |
| `DB_PASSWORD`                                          | ✅   | 위 계정 비밀번호                                                          |
| `REDIS_HOST`                                           | (local만) | local `localhost`. prod는 compose에 `redis`로 고정돼 있어 불필요     |
| `REDIS_PORT`                                           |      | 기본 `6379`                                                               |
| `JWT_SECRET`                                           | ✅   | Access Token 서명 키 (Base64, 256bit 이상 권장)                           |
| `JWT_REFRESH`                                          | ✅   | Refresh Token 서명 키                                                     |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`            | ✅   | GitHub OAuth App 자격증명                                                 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`            | ✅   | Google OAuth 클라이언트 자격증명                                          |
| `FRONTEND_URL`                                         | ✅   | 소셜 로그인 완료 후 리다이렉트 대상. prod `https://dev-community-neon.vercel.app` (Vercel) |
| `CORS_ADDITIONAL_ORIGINS`                              | ✅ (prod) | **신규.** 프론트(Vercel)가 백엔드와 다른 도메인이라 필수. 콤마로 여러 origin 구분 가능 |
| `COOKIE_SAME_SITE`                                     | ✅ (prod) | **신규.** 프론트/백엔드가 서로 다른 도메인이라 `None` 필수(단일 서버 시절엔 불필요했음). `cookie.secure=true`와 함께 켜져 있어야 브라우저가 쿠키를 허용 |
| `PORTONE_API_SECRET`                                   | ✅   | PortOne V2 API secret                                                     |
| `PORTONE_STORE_ID`                                     | ✅   | PortOne 상점 ID                                                           |
| `PORTONE_CHANNEL_KEY`                                  | ✅   | 결제 채널 키                                                              |
| `PORTONE_WEBHOOK_SECRET`                               | ✅   | 웹훅 서명 검증 시크릿 (`whsec_...`)                                       |
| `PORTONE_WEBHOOK_NOTICE_URL`                           |      | 웹훅 라우팅 URL (선택)                                                    |
| `MAIL_USERNAME` / `MAIL_PASSWORD`                      | ✅   | 비밀번호 재설정 메일 발송용. Gmail이면 **앱 비밀번호** 발급 필요          |
| `GEMINI_API_KEY`                                       |      | 미설정 시 AI 요약/태그 추천 기능만 비활성화, 나머지는 정상                |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_NICKNAME` | ✅   | 최초 기동 시 자동 생성되는 관리자 계정 (`ADMIN_NICKNAME` 기본값 `관리자`) |

> `docker-compose.prod.yml`은 위 값에 더해 `SERVER_FORWARD_HEADERS_STRATEGY: framework`를 컨테이너 환경변수로 직접 주입한다 (Nginx 뒤에서 `X-Forwarded-*` 신뢰 → OAuth `redirect_uri`가 `https`로 생성되도록).

| --------------------------- | ------------------- | ----------------------- | --------------------------------------------------------------------------------- |

### 3.3 GitHub Secrets (CI/CD)

> Secret **이름은 `EC2_*`로 그대로 남아있지만**, GCP e2-micro로 이전한 뒤 값만 그 서버를 가리키도록 변경된 상태(`deploy.yml`도 이름을 안 바꿔서 그대로 참조 중).

| Secret             | 용도                                                    |
| ------------------ | ------------------------------------------------------- |
| `GITHUB_TOKEN`     | (자동 제공) GHCR 로그인/푸시                             |
| `EC2_HOST`         | 배포 대상 서버 퍼블릭 IP/도메인 (현재 값: GCP e2-micro)  |
| `EC2_USER`         | SSH 계정 (예: `ubuntu`)                                  |
| `EC2_SSH_KEY`      | SSH 개인키                                               |
| `EC2_PROJECT_PATH` | 서버에서 저장소가 클론된 경로 (현재 값: GCP 인스턴스 경로) |

Vercel(프론트)은 GitHub 연동 자동 배포로 이 저장소의 GitHub Secrets/Actions와 무관하게 별도로 배포.

## 4. 로컬 개발 환경

### 4.1 사전 준비

- JDK 21 (Temurin 권장)
- Node.js 20+
- Docker / Docker Compose

### 4.2 백엔드

```bash
cd backend
cp .env.example .env          # 값 채워넣기 (DB_HOST=localhost, REDIS_HOST=localhost)
docker compose up -d          # MySQL(3306) + Redis(6379)
./gradlew bootRun             # profile: local, http://localhost:8080
```

Swagger UI: `http://localhost:8080/swagger-ui/index.html`

### 4.3 프론트엔드

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

### 4.4 배포 환경과 동일하게 한 번에 (선택)

```bash
# 저장소 루트, backend/.env 필요
docker compose -f docker-compose.prod.yml up -d --build
```

> 로컬에서 이 방식으로 띄우면 nginx.conf가 `dev-com.duckdns.org` 인증서를 참조하므로 443 서버 블록에서 기동 실패할 수 있다. 로컬 통합 테스트는 보통 4.2 + 4.3 조합을 사용.

### 4.5 테스트

```bash
cd backend && ./gradlew test        # 레이어별 테스트, profile: (기본)
cd frontend && npm run test         # Vitest + testing-library
```

## 5. CI/CD 파이프라인

### 5.1 CI (`.github/workflows/ci.yml`)

**트리거**: `main` push, `main` 대상 PR

```
build-and-test (항상)
  ├─ MySQL 8.0 / Redis 7 서비스 컨테이너 기동
  ├─ JDK 21 셋업 (gradle 캐시)
  ├─ ./gradlew test  (SPRING_PROFILES_ACTIVE=ci)
  └─ 테스트 리포트 발행 (dorny/test-reporter) + 아티팩트 업로드(7일)

build-and-push-images  (push 이벤트에서만, build-and-test 성공 후)
  ├─ GHCR 로그인
  ├─ backend 이미지 빌드/푸시 → ghcr.io/.../dev_community-app:{latest, <sha>}
  └─ nginx 이미지 빌드/푸시   → ghcr.io/.../dev_community-nginx:{latest, <sha>}
     (docker buildx + GHA 캐시)
```

Vercel이 GitHub push를 감지해 소스에서 직접 빌드·배포

> **이미지 빌드를 CI에서 하는 이유**: GCP e2-micro(RAM 1GB)에서 redis/app이 메모리를 나눠 쓰는 상태로 Gradle 빌드를 돌리면 스왑까지 밀려 사실상 멈춰버림(구 EC2 t2.micro 시절부터 있던 문제로, 서버를 옮긴 뒤에도 동일). 빌드는 러너, 배포 서버는 pull만.

### 5.2 CD (`.github/workflows/deploy.yml`)

> 워크플로우 job 이름은 여전히 "Deploy to EC2"이고 SSH 대상도 `secrets.EC2_HOST` 등 EC2 이름의
> 시크릿을 그대로 사용하지만, 실제 접속 대상은 GCP e2-micro 서버(§3.3 참고). 프론트(Vercel)는 이
> 워크플로우와 무관하게 GitHub push 시 Vercel이 자체적으로 빌드·배포함.

**트리거**: `CI` 워크플로우가 `main`에서 `completed` && `conclusion == success`

```
deploy (SSH: appleboy/ssh-action)
  cd $EC2_PROJECT_PATH
  git pull origin main                              # compose 파일/nginx.conf 갱신 반영
  docker login ghcr.io
  docker compose -f docker-compose.prod.yml pull    # 새 이미지 받기
  docker compose -f docker-compose.prod.yml up -d   # 변경된 컨테이너만 재생성
  docker image prune -a -f --filter "until=24h"     # 오래된 이미지 정리
```

DB 스키마는 `ddl-auto: update`로 앱 기동 시 자동 반영.

## 6. 프로덕션 최초 배포 절차

### 6.1 GCP e2-micro 준비

> 2026-08-27 이전 기준. 원래는 AWS EC2였고 큰 틀은 동일. Secret 이름은 마이그레이션 후에도 `EC2_*`를 그대로 사용(§3.3).

1. Docker / Docker Compose 설치
2. 저장소 클론 → `EC2_PROJECT_PATH`(GCP 인스턴스 경로)에 위치
3. 프로젝트 루트에 `.env` 작성 (3.1 표의 모든 필수값, prod 기준)
   - `DB_HOST=<Aiven 호스트>`, `DB_PORT=<Aiven 포트>`, `DB_SSL_MODE=REQUIRED`
   - `FRONTEND_URL=https://dev-community-neon.vercel.app`
   - `CORS_ADDITIONAL_ORIGINS=https://dev-community-neon.vercel.app`, `COOKIE_SAME_SITE=None`
   - `REDIS_HOST`는 compose에 고정값이라 안 넣어도 됨
4. GCP 방화벽 규칙: 22(SSH, 내 IP), 80, 443 인바운드 허용
5. DuckDNS 도메인이 GCP 인스턴스의 퍼블릭 IP를 가리키도록 설정

### 6.2 HTTPS 인증서 최초 발급

nginx.conf의 443 서버 블록은 인증서 파일이 있어야 기동하므로 **순서가 중요**

```bash
# 1) 80 포트만 뜨는 임시 상태로 먼저 기동하거나, 443 블록을 잠시 주석 처리
docker compose -f docker-compose.prod.yml up -d nginx

# 2) certbot으로 최초 인증서 발급 (entrypoint를 반드시 덮어써야 함 -
#    기본 entrypoint는 renew 무한루프라 certonly 인자가 무시됨)
docker compose -f docker-compose.prod.yml run --rm --entrypoint certbot certbot \
  certonly --webroot -w /var/www/certbot -d dev-com.duckdns.org \
  --email <이메일> --agree-tos --no-eff-email --non-interactive

# 3) nginx.conf에 443 서버 블록 활성화 후 전체 기동
docker compose -f docker-compose.prod.yml up -d
```

이후 `certbot` 컨테이너가 12시간마다 `certbot renew`를 시도하고, 갱신 시 nginx는 자동 반영(볼륨 공유)됨. 실제 반영을 위해 필요 시 `docker compose exec nginx nginx -s reload`.

### 6.3 외부 서비스 콜백/웹훅 등록

| 서비스              | 등록할 값                                                                          |
| ------------------- | ---------------------------------------------------------------------------------- |
| GitHub OAuth App    | Authorization callback URL: `https://dev-com.duckdns.org/login/oauth2/code/github` |
| Google OAuth Client | 승인된 리디렉션 URI: `https://dev-com.duckdns.org/login/oauth2/code/google`        |
| PortOne 콘솔        | 웹훅 URL: `https://dev-com.duckdns.org/api/payments/webhook` (HTTPS 필수)          |
| Gmail               | 2단계 인증 활성화 → 앱 비밀번호 발급 → `MAIL_PASSWORD`                             |

> 로컬(`application-local.yml`)의 GitHub scope는 `read:user`뿐이고 prod는 `read:user,user:email`이다. 이메일 비공개 사용자의 대표 이메일 조회 때문.

## 7. 운영 태스크

| 작업                 | 명령 (GCP 서버 프로젝트 루트, `EC2_PROJECT_PATH`)                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 전체 상태 확인       | `docker compose -f docker-compose.prod.yml ps`                                                                    |
| 앱 로그              | `docker compose -f docker-compose.prod.yml logs -f app`                                                           |
| 특정 컨테이너 재시작 | `docker compose -f docker-compose.prod.yml restart app`                                                           |
| 수동 배포(재pull)    | `docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d`               |
| 인증서 상태          | `docker compose -f docker-compose.prod.yml run --rm --entrypoint certbot certbot certificates`                    |
| DB 접속              | Aiven이 관리. Aiven 콘솔의 Quick connect 또는 `mysql -h $DB_HOST -P $DB_PORT -u $DB_USER -p --ssl-mode=REQUIRED $DB_NAME` |
| DB 백업              | Aiven 콘솔의 자동 백업/스냅샷 사용 (관리형이라 서버에서 직접 `mysqldump` 실행 불필요)                                |
| 업로드 파일 위치     | 볼륨 `uploads_dev_community` → 컨테이너 `/app/uploads`                                                             |

- **JVM 메모리**: app 컨테이너는 `-Xmx256m -XX:MaxMetaspaceSize=200m -XX:+UseSerialGC -XX:ReservedCodeCacheSize=64m -Xss256k` (GCP e2-micro, RAM 1GB 제약. 컨테이너 자체는 `mem_limit: 500m`).
- Redis는 영속 볼륨이 없으므로 재시작 시 Refresh Token / 로그인 실패 카운트 / 조회수 중복키가 전부 초기화 (전 사용자 재로그인 필요).

## 8. 알려진 함정 (배포 관련)

| 증상                                                | 원인                                                               | 대응                                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 배포 환경에서만 소셜 로그인 `redirect_uri_mismatch` | Nginx가 HTTPS 종료 후 HTTP로 프록시 → Spring이 `http://` 콜백 생성 | `server.forward-headers-strategy: framework` (prod yml) + Nginx `proxy_set_header X-Forwarded-Proto $scheme` 확인 |
| 배포 서버에서 배포가 멈춤/스왑                      | e2-micro(1GB RAM, 구 EC2 t2.micro도 동일)에서 Gradle 이미지 빌드    | 빌드는 CI에서만, 서버는 `pull`만                                                                                  |
| `OutOfMemoryError: Metaspace`로 로그인 등 API 500   | GCP e2-micro 이전 직후 `-XX:MaxMetaspaceSize=128m`이 너무 작았음    | 200m으로 완화(현재 값). 컨테이너 `mem_limit`(500m) 안에는 여전히 들어옴 (PR #168)                                  |
| 이전 직후 API 응답이 눈에 띄게 느려짐(7초대)         | Aiven(인도 리전) ↔ GCP(미국 리전) 간 물리적 거리로 왕복 지연 263ms | Aiven을 동일 무료 등급 내 북미 리전으로 재배포 → 38ms, 응답 1초대로 개선 (PR #167)                                 |
| certbot `certonly` 인자가 무시됨                    | 기본 entrypoint가 `renew` 무한루프                                 | `run --rm --entrypoint certbot certbot certonly ...` 로 덮어쓰기                                                  |
| 인증서 없이 배포 시 nginx 컨테이너 기동 실패        | nginx.conf 443 블록이 인증서 파일 참조                             | 인증서 발급 후 443 블록 활성화 (6.2 순서)                                                                         |
| Vercel에서 새로고침/직접 접속 시 404                | SPA는 클라이언트 라우팅이라 서버엔 해당 경로 파일이 없음            | `frontend/vercel.json` rewrite로 `/index.html` 폴백 (단 `/api`, `/ws`, `/oauth2`, `/login/oauth2`는 제외해야 함 — 한 번 이 경로들까지 가로채는 버그가 있었음, PR #165·#166) |
| Swagger 접속 시 Vercel로 리다이렉트됨               | `dev-com.duckdns.org`는 이제 API 전용 도메인 — nginx의 캐치올(`location /`)이 프론트(Vercel)로 302 리다이렉트함 | `/swagger-ui/`, `/v3/api-docs`는 캐치올보다 먼저 오는 명시적 프록시 블록으로 처리 (단, prod는 springdoc 비활성이라 404가 정상) |
